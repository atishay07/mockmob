## Proven implementation cause

V713 starts from the V76-built request/schema, then `factoryEvidenceV713.mjs` overwrites the entire system prompt with `compactSystemV713(stage)`. The captured first-wave body has no canonical fit anchors in system or user instructions. The canonical inherited `CUET_FIT_PROMPT` supplies each criterion's 0–3 anchors and exact-three-non-key challenge semantics (`factoryEvidenceV76.mjs` and `cuetFit.mjs`). V713 compact instructions retained neither. The structured schema can require three array items and enumerate A-D, but cannot express the dynamic condition “all and only options other than this response's solved_key.” The actual Luna output A/B/C therefore satisfies shape while violating semantic coverage; the local `optionChallengeVerdict` correctly rejects it. This is not a defect in the deterministic 0–3 interpretation: `cuetFitVerdict` correctly interprets the declared level fields and recomputes score/gates.

For `f-c797dd7934bbaf7c`, the additional fit result is a genuine later quality-gate failure in the recorded output: Luna supplies all four level values as 0 with blank evidence (score 3); Gemini returns all 3s. As anchors are absent from that request, Luna's ratings are not interpretable as rubric evidence. This doesn't erase the separate source-support challenge-array failure, nor establish a pass. The same absent-anchor ambiguity appears in `f-155...`, `f-80...`, and `f-793...`.

The one explicit independent issue outside this prompt regression is f-f84: no precise source wording in the captured excerpt itself says that this particular “old production machine” was held as a fixed asset. Normal CUET reading supports that implication, but the deterministic condition guard marks it as answer-changing. Retain this risk for adjudication; do not relabel or repair the frozen case.
