## Additive lifecycle infrastructure milestone

Implemented only new `scripts/pipeline/lib/ideaAllocationV76.mjs` and `scripts/pipeline/tests/ideaAllocationV76.test.mjs`; frozen V75 allocation/pilot files and frozen V76 academic modules are untouched. No real intent, registration, provider call or database mutation occurred.

The module reserves an entire campaign through a flushed atomic immutable intent **before** the exact preregistration marker exists. Per-job identities, family identity, exact refs, expected marker path/hash and matching-reuse policy are fixed in that intent. An atomic JSON index is derived from intents; it is not permission to free their ideas. Restart consumes final intents and complete unrenamed intent checkpoints, preserves snapshot-only uncertainty, and blocks on incomplete/contradictory checkpoints. An absent or mismatching marker remains reserved/uncertain; an exact marker appends a commit receipt. A committed allocation never reverts when its marker disappears. There is no reset or release API.

Exclusive directory ownership includes PID and random nonce, checked before every operation. Live owners and uncertain liveness/metadata are refused. A proven-dead owner is retired with its unchanged nonce/metadata into retained history under an exclusive recovery gate. Unknown or interrupted recovery is refused instead of guessed free. A failed file flush/rename leaves its checkpoint and blocks progress. File flushing and atomic renames provide process-crash protection; full power-loss guarantees depend on the host filesystem.

Ordering consumption checks overlapping individual exact source spans, not only bundle equality. Matching checks both identical bundles and overlapping Oxford lexical target IDs; revising the same word's source version/support hash cannot bypass overlap. Default `deny_overlap` rejects reuse even within a campaign. Explicit alternatives are `allow_within_campaign` (cross-campaign overlap still refused) and `allow` (overlap permitted, exact bundles still refused). These are lifecycle policies, not academic proof of novelty. Historical V75 rows and caller-provided inventory/all-attempt context are imported read-only; quarantined attempts still consume their tracked ideas. Historical files are never rewritten.

Later qualified V76 preparation must: (1) read and bind the current inventory/all attempts and historical V75 ledger; (2) fix all 40 jobs and exact preregistration bytes/hash; (3) open the new allocator under a single owner; (4) call `reserve({campaignId,jobs,registration:{path,sha256}})` **before any preregistration marker write**; (5) persist the frozen campaign/inputs and exact marker atomically; (6) call `reconcile()` and verify committed allocation outcomes before allowing authoring; (7) retire ownership with `close()`. Restart reopens and reconciles the same intent and marker; it never purchases replacements or frees absent-marker reservations. Do not call `openIdeaAllocatorV76` on the default path before exact V76 qualification passes: opening itself creates a lifecycle owner lock. The V75 preparer's marker-first allocation sequence is not reused.
