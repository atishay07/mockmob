# Key cards gap brief (31 Oct 2026, second pass)

The first links pass linked about half of the live questions to a Key card ("The line you needed": when a student gets
a question wrong, the site shows the 1-2 NCERT cards that decide it). This pass closes the gap. For every live question
in your scope that has **no link yet**, decide one of three things.

- **LINK:** a published card already holds the deciding NCERT line and the first pass missed it. Link it.
- **NEW:** the NCERT chapter text states the deciding line (a fact, definition, list item, rule, formula or entry
  format), but no published card holds it. Write a new card for that line and link it.
- **NONE:** NCERT text does not decide the answer (the fact is not in the book, the question needs multi-step
  reasoning beyond a single rule, or the question looks flawed). Leave it out. A wrong link teaches the wrong thing.

## Read first
- `ncert-books/AUTHOR-BRIEF-2026-10-31.md` and `ncert-books/LINKS-BRIEF-2026-10-31.md`. Both bind, apart from the
  output paths below.
- The content spec: `mockmob-next/docs/brain/intel-1031/KEYCARDS-CONTENT-SPEC.md`.

## Inputs
- **Published cards:** `wt-1031-keycards-web/data/keycards/decks/<subject>.json`.
- **Existing links:** `wt-1031-keycards-web/data/keycards/links/<subject>.json`. Skip every question already in it.
- **Drafts:** `ncert-books/drafts/<code>.json`. These include quarantined cards. Do not reuse a quarantined card's id
  or its exact quote.
- **Live questions:** read-only, through Supabase `execute_sql` (project `isrxrxzjocewrdureyhp`).
  - SELECT only. Never insert, update, delete or apply.
  - Filter with `status = 'live' and coalesce(is_deleted,false) = false`.
  - Resolve each question's chapter with `resolveChapter` from `wt-1031-keycards-web/data/cuet_syllabus.js`. Skip
    retired chapters.
- **NCERT text:** pdftotext and pdfium (`scripts/keycards/pdfium_pages.py`) on `ncert-books/pdf/<code>.pdf`.
  - Render a page to PNG with pypdfium2 when you need to see a table or formula.

## Writing new cards
- **Where:** append the card to `ncert-books/drafts/<code>.json`, the NCERT chapter its quote comes from, and only for
  codes in your scope.
  - Never edit, reorder or remove existing cards.
  - Never touch another agent's codes.
- **Content:** exactly the AUTHOR-BRIEF card format: exact quote on the cited printed page, front, back, blanks,
  kind, importance, and the chapterKey and unit from the CUET 2026 syllabus.
- **Marker:** add `"addedIn": "gap-1031"` to every new card.
- **Ids:** unique across the published deck and every draft of the subject. Same scheme:
  `kc.<subject>.<chapter-slug>.<kind>-<short-slug>`.
- **Scope:** one card per deciding line. Several questions that hinge on the same line share one card.
- **Self-check, the gate:** from `C:\Users\atish\Desktop\mockmob copy\wt-1031-keycards-web` run
  `KEYCARDS_OUT_DIR=<your scratch folder>/out node scripts/keycards/validate.mjs --machine-only --subject=<subject>`.
  - None of your new ids may appear in `<scratch>/out/quarantine/<subject>.json`. Fix them or remove them.
  - Never write into the repo.

## Output
- **Links:** `ncert-books/links/gap-<your task name>.json` = `{ "<questionId>": ["<cardId>", ...] }`.
  - Keys sorted, at most 2 cards per question, best first.
  - Card ids are published ids, or new ids you appended this pass.
- **Notes:** `ncert-books/links/gap-<your task name>.notes.json` =
  `{ "suspectKeys": [{ "id", "why" }], "outsideNcert": n, "reasoningOnly": n }`.
  - `suspectKeys` lists questions whose stored correct answer disagrees with NCERT.
- **Scratch:** scripts go only in your own `kc-gap-<name>` folder inside your temp folder.
- Do not commit. Nothing else changes.

## Return
Four lines:
1. Questions examined, LINK, NEW, NONE.
2. New card ids added, by code.
3. Suspect answer keys found.
4. The weakest chapter and why.
