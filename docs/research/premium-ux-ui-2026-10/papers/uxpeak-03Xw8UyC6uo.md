## Generalization [I]

A model building UI should start by identifying the user, job-to-be-done, state, environmental constraints and the actual next action. Build a navigable wireframe/state machine before typography polish. Test critical flows, not just screenshots. Define page-level criteria for success and failure. If there's no actual research, label assumptions and request validation; do not manufacture study quotes.

## Specific application [I]

In MockMob, the question attempt, solution review, next-best-move recommendation, credit use and incomplete/expired exam must be described as connected journeys. A great score card is only good UX if students can interpret it, understand what caused it, and take a next step. In Circuit, permission gates and verification should be designed as stateful experiences, including loading, retry, denied and success.
